# 威胁模型与限制

信任：服务器代码、启动配置、凭证映射、SQLite 文件及操作系统账户。攻击者可控制请求文本、工具建议、记忆值和检索文档内容；不能拥有服务器文件写权限。UserContext 只能由 HTTP 认证映射产生。直接调用 Python 时，调用者属于受信任服务器代码；不是远程授权接口。

确定性边界：工具名称和参数白名单、同租户对象权限、独立审批者角色、发起者与参数摘要绑定、原子消费、按租户/用户/会话/模式隔离记忆。过期采用服务端时间；SQLite BEGIN IMMEDIATE 串行化写事务。

保持小范围：
- 数据仅为假用户、假工资、假工单。业务表不存任何真实 API key。
- 审计只存 request_id、身份、事件和枚举原因；不存提示词、header、原始参数或上游错误。
- /runs 只允许原发起用户访问。保存的回答会脱敏，但自由文本检测并非完整 DLP。
- 无跨请求聊天历史、无共享答案缓存；偏好键仍是非可信数据，白名单不能防止所有模型注入。
- RAG 仍为原关键词 + trusted 过滤实验，不冒充向量检索；独立 RAG 项目负责该部分。
- demo_auth.json 是本机假身份映射，不具备密码登录、远程撤销服务、速率限制或生产 SSO。修改凭证映射文件需要重启服务；应用内执行会重新检查当前 registry 的审批角色。
- 本地文件攻击、主机管理员、资源耗尽、数据库备份加密、生产数据保留策略不在此实验范围；不对公网部署。
- 写入合成工单只在单次 Agent run 内去重；跨请求幂等键未实现。高风险审批一条记录只消费一次，但新申请仍可再次审批。
- 本轮真实模型 API、收费、模型防御率和真人学习验收均未执行。

迁移选择：旧 JSON 可能已经污染且缺少可信命名空间，不能自动赋予某个用户并导入 secure；保留旧文件，仅使用新 SQLite 数据库。生产迁移需可信来源与明确所有者。

学习验收（留给项目本人填写）：修改了什么；旧行为如何复现；哪项断言证明修复；解释 approve 与 execute 的角色差别；解释为什么 check-then-delete 不足以防重放。不要把 AI 生成代码直接表述为本人已独立完成全部设计。
